## 2026-10-26 08:3x · accelerator 任务执行前等待空闲 NPU 卡（commit 70f54d6）

- **问题与证据**：用户指出本机为 8×910B4 服务器，且此前要求"每次运行前检查卡数量，够就跑、不够就等"。实证：`npu-smi info` 8 卡全空闲时，PR 201949（t-20261026-072104-45b667）仍有测试以 "Need at least 4 accelerator devices" 跳过（`docs/run_test/台账/未分类错误.md` U-new-000002）；executor 此前无任何卡可用性检查，外部任务占卡时测试会与外部负载抢卡。
- **根因**：executor 阶段流转中没有卡资源门禁；`torch.cuda.device_count()=0`（vs `torch_npu.npu.device_count()=8`）导致 pytorch 跳过门禁读数为 0 是另一独立问题（见遗留）。
- **修改与行为**：新增 `run_test/npu_cards.py`（npu-smi 探测：`info -t proc-mem` 无进程 + `info -t health` OK；`wait_free_cards` 轮询等待；可见卡不足立即诊断；`python -m run_test.npu_cards` 可独立运行）与 `run-test/tools/wait-npu-cards.sh` 薄壳；executor 在 preflight 之后、进 testing 之前等卡（下载/安装照常先做——用户明确要求卡不足时 install 不阻塞），超时 blocked 且空原因有兜底；`wait_free_npu_cards` 未配置不启用（不猜默认值）；runner.run_function 增加 extra_env 注入参数（本轮未使用）；settings(.example).json 启用 1 卡/30s/21600s。**应用户要求门禁位置从"下载前"改回"执行前"（中途一版放下载前，已纠正）。**
- **验证**：355 项回归 + verify.sh 四场景验收通过；真机实证：8 卡空闲 `--need 8` 秒过；占住卡 0 时识别 7/8、等待 6s 超时 exit 1；负载结束恢复 8 卡。单测 9 项（解析/忙闲健康/等待/超时/超容量/cpu 任务不触发/未配置不启用/空原因兜底）。
- **限制与遗留**：①本轮仅串行等待、不钉卡——按测试真实需求（world_size/清单证据）申请设备与执行期租约未实现，query 与运行间存在外部抢卡窗口；②选择期 discovery 不经门禁；③pytorch 测试 `torch.cuda.device_count()=0` 导致的 skip 是 harness 层映射问题，未在本条修复（需单独适配，不伪造计数）；④npu-smi 输出格式若升级变化需跟进解析；⑤`test_recovery_lease::test_os_releases_lease_after_process_termination` 偶发 flaky（与本次无关：干净 stash 树上复现失败，后续整轮 355 全过），待单独排查；⑥等待日志的"已等"时长可因轮询间隔越过 deadline 略超 timeout 值（粒度现象，无害）。

## 2026-10-26 07:0x · 拆分包格式适配（commit 9278d0a）

- **问题与证据**：上游 10-22 19:39（北京）起将全量 wheels 包拆为 `wheels-pytorch-{sha}-…-v2`（torch+torchvision）+ `wheels-torchnpu-{npu}-{sha}-…-v2`（torch_npu），旧命名匹配完全失配，23 日起零入队（用户 10-26 上午预警"包改名"）；OBS 桶实证 613 对象/159 束/109 配对全为旧格式产物，新格式对象对 cycle 不可见。
- **根因**：`wheel_identity` 正则不识别拆分格式；executor 假设 torch_npu 在主体包内；tasks 表无独立 npu 对象字段。
- **修改与行为**：artifacts 识别两种拆分格式 + select_bundle 按名配对（无 -vN 的 wheels-torchnpu 仍视为另一产品）；tasks 表新增 obs_wheels_npu_url/version（含老库迁移）并纳入候选去重键；cycle 三对象齐才入队；executor 下载第三对象、跨包找 wheel、npu 短 commit 与包内 git_version 互核。
- **验证**：338 项回归 + 四场景验收通过；实机：cycle 与手工回填（manual-bucket-backfill-20261026 规则）按拆分包入队 10-23 起全部三件齐包体；首个拆分包任务 PR 201949 端到端跑通（4 pass/3 skip，npu commit 从独立包回写）并自动发布飞书。
- **限制与遗留**：多变体 sha 的链选择发生在手工回填脚本层（选 npu 最新链），cycle 路径对歧义仍报 ambiguous 等人工；ciflow trunk PR-head 包按口径排除。
- **过程教训**：run_cycle 内 `from .artifacts import …` 为循环体惰性导入，编辑运行中管道的代码会被常驻进程在下一轮"吸入"产生新旧混合状态（07:03 曾入队 2 个缺 npu 绑定的任务，作废重建）；改完代码必须 start.sh stop/start 重启常驻服务。
