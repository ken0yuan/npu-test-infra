# 按具体测试证据选择用例

源码候选与真实运行节点分开。选择器在控制环境读取源码，不导入测试；
Executor 安装当前任务的构建包后，在原有资源租约下验证运行节点。

## 关联及优先级

`test_catalog.py` 为 `test/` 和 `tools/test/` 建立源对象目录，区分测试入口候选、
普通模板、helper、嵌套函数和 Triton JIT 内核。helper/内核继续参与调用关联，
但不会因 `test*` 名称直接进入执行清单。直接调用、`self` helper、嵌套 helper、
`kernel[grid](...)`、同一产品模块内公开 wrapper 到被改 helper 的关系保留链路。
作用域中的参数和局部绑定不会冒充同名导入的函数。

每个候选只包含它自己的证据、源函数、影响组和等级。一个测试的直接引用
不能提高同文件其他方法的等级；类级共享配置也不影响无关类。

| relevance | 实际依据 | 对外兼容列表 |
|---|---|---|
| 0 | 被直接修改或新增的测试入口 | p0 |
| 1 | 变更 helper 的调用者、实际调用变更符号的测试 | p0 |
| 2 | 符号引用、受影响的共享 fixture/绑定/类上下文 | p1 |
| 3 | 导入兼容性 canary、路径或 PR 提示 | p1 |

PR 文字是发现线索，不能把一个只有名称提示的用例升级为已验证的回归测试。
静态调用/引用也不证明断言验证了变更行为，未解析关系继续列为覆盖缺口。

先按证据强度为不同影响组取代表，再补重复组中的测试；同等级按文件轮转及
稳定身份决定顺序，不按方法行数决定验证价值。普通 import canary 默认每个
变更源模块至多一个，其余在 `redundant_canaries` 保留去向，不凑满执行预算。

## 预算与补位

默认 15 是源函数家族预算。同一源函数的 CPU/accelerator 两个分支共用一个
家族名额，但各自保留完整执行身份。`plan_to_manifest(include_reserve=True)`
输出有序备用候选及 `selection` 元数据，队列校验并持久化这些字段。

只有前一批家族的所有通道均在成功收集后找不到对应运行节点，才释放该家族
名额并激活备用收集任务。优先使用同影响组且证据不弱于原项的备用测试。
补位继续进入同一调度队列；其他 CPU/NPU 测试可以正常推进，不另建执行池。
原缺口仍保留 `no_result`，不能因替代用例完成就声称原行为已覆盖。
环境异常、导入失败和 NPU 初始化失败不触发这种自动替换。

每个源函数/通道仍最多 100 个真实实例。先选变更中相关的参数 token，再增加
参数分层的代表性，超出部分保留准确的 deferred 身份并标记 partial。
不会以补位或抽样降低多卡需求；partial/no_result 不刷新完整基线。

## tools 与实际入口校验

`test_suites.py` 统一目录、工作目录和收集参数。tools 源码和依赖一起从包中
抽取；通过真实 tools 包路径及 pytest importlib 模式导入，不将未构建的源码
torch 加入解释器搜索路径。未声明硬件条件的 tools 测试只进入 CPU 通道。
部署时同时在 `baseline_dirs` 登记 `tools/test`，保留其他现有目录；否则严格
结果校验会拒绝未归属目录的 tools 结果。示例配置已包含该目录。

运行时同时核对节点与展开后的函数身份。PyTorch 的设备生成条件关闭时，
pytest 有时仍能收集一个 unittest 模板；若实际可调用函数仍需要 device/dtype
等必填参数，该模板不会作为合法用例执行。普通 pytest fixture 参数不受此
检查影响。收集回执保留原始节点、声明和未绑定参数。

## 确定性空计划与边界

空计划保存结构化 `needs_review` 原因并返回独立退出码 4。SelectionPool
保留 blocked 语义，但不会将同一确定性空计划反复下载、重试三次。
锁争用仍等待；临时失败仍使用原有有界重试。没有扩展既有 PR 排除列表，
不把纯 `.agents/...md` 的零候选假装成测试通过。

现有显式 AST 关系不穷尽动态反射、跨未索引模块调用或 C++ 行为覆盖。
C++/路径推荐仍不能证明验证了具体 native 变更。收集缓存不跨任务安装环境；
真实收集仍绑定源码、解释器、执行通道、环境和可见卡范围。

本批不重构 bugmonitor；完整收集回执是入口验证的依据。生产前用精确源码
重放 PR 201073、201837、202389，并区分源码筛选正确、当前环境入口可用和
实际测试通过三种结论。验证不覆盖 torch-npu、驱动或固件的修复。
