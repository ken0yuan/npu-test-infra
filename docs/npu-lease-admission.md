# NPU 租约、收集与初始化探针

执行端只在持有对应物理卡的 OS 租约后启动 accelerator 子进程。
串行和并行都使用 `CardPool`，不再使用 PR 级的默认 NPU0 预检或
`wait_free_npu_cards` 全批门禁；该旧配置不参与新调度。单独的等卡 CLI 保留。

1. 源函数收集任务按声明或保守推断的卡数申请租约，设置
   `ASCEND_RT_VISIBLE_DEVICES`，运行独立初始化探针，再收集真实测试身份。
2. 把每个源函数／执行通道至多 100 个实例及剩余未选实例写入执行清单。
   收集租约释放后，实例进入同一个调度队列，按各自需求重新领卡。
3. 探针、收集和执行子进程继承本次卡锁及执行环境锁 FD。每次调用显式传 FD，
   不修改共享 runner 的线程间状态；收集缓存仍绑定源码、环境和可见卡范围。
4. CPU 收集完成即可展开 CPU 实例，不必等待其余 NPU 收集结束。
   收集和执行共享现有动态 CPU 线程预算，不另建一份并发预算。

## 就绪探针与结果语义

探针在独立短进程中逐个初始化租约内的逻辑设备，获取流、分配小张量、
执行矩阵乘及同步。逻辑卡号按可见范围映射，记录对应的物理卡集合。
成功必须有退出码与完整 JSON 完成回执，不能用 `device_count` 或空输出代替。
普通测试进程的 lazy-init、fork、分布式启动语义不因此被预热改变。

健康状态仅在同一任务／wheel 环境内按物理卡缓存，默认 60 秒。
`executor.npu_readiness_cache_seconds` 可调整缓存时间；
`executor.npu_init_timeout_seconds` 默认 300 秒，限制单次探针。
只有识别到 HDC/TSD/507033 初始化签名才以全新子进程重试一次。
每次尝试均保留 stdout、stderr、卡号、子进程 PID、阶段及可获取的对应 CANN 日志。

探针明确定位某张卡失败时，只在本任务的池内隔离该卡；没有卡级定位的
后端环境失败会停止本任务后续 NPU 准入，不宣称所有卡都有硬件故障。
健康卡数量不足原多卡要求时返回未执行证据，绝不自动减少卡数。
这些项保存 `no_result`、`env_init_error` 或未分类的 `npu_probe_error`，
CPU 项继续运行并一起落库；未完成项不产生假计数、不刷新基线。
外部进程占用但尚无故障证据的卡仍按 `resource_wait` 等待。

探针成功只代表当时的准入检查，不保证下一测试进程初始化一定成功。
真实 pytest 的异常、原生信号崩溃和 JUnit 结果仍按原有规则保留。
本次不修改 torch-npu 的 `noexcept`、驱动、固件或测试函数。

## 验收重点

- 非零物理卡的逻辑索引、mask 和继承 FD 对齐。
- NPU 忙时 CPU 实际执行；NPU 初始化失败时 CPU 结果正常落库。
- 收集结束后释放租约，一个家族的多个单卡实例可以并行使用多张卡。
- 多卡需求、100 实例上限、完整覆盖身份和基线规则不退化。
- 已识别故障只重试一次；非初始化故障不重试；第一次失败证据不丢失。
