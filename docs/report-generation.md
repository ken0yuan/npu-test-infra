## 展示契约

1. 文档标题 `PR#编号`；三级标题 `PR #编号` 链接至对应 GitHub PR。
2. 显示 PyTorch / torch-npu 提交；有真实合入时间时显示该时间。
3. 两行六列统计表，列名和顺序沿用历史样例。
4. 基线前后对比使用完整测试标识和实际设备，保留首次建立、覆盖更新、不可比、无结果及缺失快照的区别。
5. 每项用四级标题默认折叠，标题含状态图标、类/函数、文件路径、设备及状态。
6. 详情展示实例计数、缺失原因、覆盖/执行状态、已知签名和日志摘要校验值；日志使用原生代码块。

## 统计语义

六列表格的单位为测试项，即一个函数在一个设备上的结果，不是参数化实例数。
按 Error > Failed > No Result > Skipped > Passed 唯一归类，保证分类之和等于 Total。
混合通过/跳过项归入 Skipped；含失败或错误的项不能因同时存在通过实例而显示为通过。
完整实例的 pass/fail/error/skip 总数单独展示，并与 PR 数据库四项汇总逐项校验。
声明 `no_result` 的项不得带完整计数；中断前 `observed_counts` 单列。四计数全零项显示
为 No Result 并发出证据提示，不改数据库的原始 `no_result_count`。

历史样例每项恰好一个结果，无法仅凭样例推断参数化混合结果的旧算法；上述混合处理是本次明确的新契约。
旧报告中的 `cuda` 原样保留在历史回归样例；新报告设备来自当前结果库，不能从旧样例复制 CUDA 执行模式。

## 数据和错误处理

- 输入：`pr_results.db` 当前 PR 行、`pr_logs/PR_<n>/baseline-diff.json`、精确函数/设备对应的日志文件。
- 读取历史对比时校验 PR、测试集合、PyTorch 提交、torch-npu 环境、计数和 no_result 状态。
- 绝不读取实时基线作为历史“before”；不可比不宣称回归或修复，计数相同不宣称同一失败。
- 拒绝重复测试项、非法计数、汇总不一致、越界证据路径及混入其他提交的档案。
- 缺日志、缺历史快照如实展示；缺快照时不将可变 PR 目录里的日志绑定到当前结果。
- 读取期间再次校验数据库行、快照与日志，变化时报错，由下一轮重试。
- 已知 C 签名只是证据标签，不把失败改为通过，不排除 PR 因果。

## 本地版本和后续上传边界

同一个数据模型生成 HTML 和飞书内容块计划。输出按内容 SHA256 分版本，全部输出成功后
更新 `current.json`；相同内容不重写、旧版本不删除。生成器没有网络和认证依赖。
常驻监测可通过 `reports.enabled` 启用，并在每轮的 `reports.errors` 保留错误。

`feishu-plan.json` 中 `append` 操作提供原生 `children/index` 请求体；`table` 操作提供建表
请求体和按行排列的 12 个单元格内容。上传器必须先获取新表格的真实单元格 ID，再填入内容，
不能复用历史文档的 ID。长日志按 8000 字符拆块、文本元素按 1000 字符拆分，无静默截断。
`feishu_publish.py` 消费该计划，实现认证、限流处理、断点记录、回读核验和旧版归档。

## 远端发布协议

1. 只使用专用环境文件中的四个飞书字段；认证头、认证响应和原始错误响应不入日志。
2. 首次上传先读取飞书 HTTPS 响应的 `Date`（UTC），以单调时钟补齐请求后的经过时间，
   再显式转换为北京时间 UTC+8。发布日志持久化首次上传 UTC 时间、`Asia/Shanghai`、
   北京日期和目标目录 token；跨午夜、断线或进程重启后沿用该日期。
   缺失或无效 `Date` 时在云端写入前停止并保留可解释错误，不使用服务器墙钟。
3. 正式位置为“目标测试目录 / 北京日期 YYYY-MM-DD / PR#编号 / 主篇及续篇”。
   日期目录下每个 PR 只占一个子目录，避免拆篇数量再次耗尽同层文档限额。
   在目标测试目录的“报告上传暂存”下，以 PR 编号和完整内容哈希建立唯一版本目录。
4. 每次写入前保存请求标识和远端原有块 ID；成功后保存新块 ID。追加内容使用飞书 `client_token`。
5. 断线后先读远端：已经写入且内容相同则继续；尚不能确认时停止，不盲目重试创建或追加。
   明确拒绝的请求可在后续轮次重试。暂存数据保持可查，失败不会更新测试计数。
6. 完整回读所有篇的全部块，校验正文顺序、PR 链接、折叠状态、表格单元格和值、全部日志文本。
7. 再次确认本地结果仍是这一版本，将全部篇移到对应日期的 PR 目录；同日同 PR 的旧版本
   （含续篇）移到该 PR 目录内的“历史测试报告”。跨日期版本保留在原日期，不删除旧文档。
   每次移动记录目的地；结果不明确时，先回读目标目录确认是否已完成。
   同一目标下的未确认移动，只有源目录仍能找到原文档才重试同一文档 ID 的移动，
   不重建文档或重复追加正文。若返回异步任务 ID，则持久化并查询任务；任务未明确失败时只等待对账。
   源文件缺失或移动目标发生变化而旧结果未确认时停止。HTTP 错误只附加数值业务码，不输出原始响应或认证头。
8. 所有篇晋升并逐篇对账，确认恰好一份同名当前篇后才记录 `published`。
   逐篇移动不是云端原子事务；中断时可能短暂可见部分新篇，但旧版本仍保留且状态仍为暂存。
   旧 `published` 回执保持零云端访问的幂等返回，旧链接、文档 ID 和本地发布日志位置不变。

上传日期属于发布日志和回执，不进入结果内容指纹。旧根目录文档由独立迁移流程整理，
使用飞书记录的 UTC 创建时间转换北京时间，并按版本集保持主篇与续篇同日存放；
不能使用服务器本地日期或 PR 合入日期冒充上传日期。迁移只移动原文档，不重建正文。

上传器的锁、回执和错误恢复状态独立于结果数据库。配置 `reports.feishu.enabled=true`
后由现有监测轮次调用；生成或上传错误按 PR 记录，其他 PR 可继续。
`FEISHU_FOLDER_TOKEN` 不参与测试结果上传，避免误写深度分析目录。
